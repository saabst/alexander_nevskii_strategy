# Невский — движок и контент

Типы, схема валидации, детерминированный движок выборов
и сценарий «Нева, 1240». ИИ не используется нигде; сети движок не требует.

## Что уже работает

```bash
npm install
npm test              # 95 тестов: шкалы, условия, граф, все прохождения
npm run validate      # проверка контента (код возврата 1, если сломано)
npm run typecheck     # строгая типизация
```

- **Движок** `src/engine/index.ts` — `startSession`, `getCurrentEvent`, `canShowChoice`,
  `applyChoice`, `calculateOutcome`, `replay`. Все функции чистые: сессия не мутируется,
  один и тот же выбор всегда даёт один и тот же результат.
- **Типы** `src/types/scenario.ts` — включая `Certainty` (`fact | recon | legend | guess`):
  статус знания есть у каждого события, варианта и реплики советника.
- **Валидация** `src/validation/schema.ts` — Zod-схема плюс проверка графа:
  достижимость событий, отсутствие тупиков, ссылки на существующие события.
- **Контент** `src/content/scenarios/neva-1240.json` — 13 событий, 32 варианта
  (12 из них зависят от пройденного пути), **4320 полных прохождений** без обрывов
  и выхода за шкалы.

## Решения, которые заложены в движок

1. **Ресурсы 0..100**, обрезка в одном месте (`clampResource`). Давление с Запада и
   Востока — тоже шкалы, но помечены `hidden`: игроку их показывают «градусником»,
   а не полосой ресурса, иначе он начнёт их минимизировать как обычный ресурс.
2. **Двойная оценка в финале.** `score` — состояние земель, `historicityScore` —
   насколько решения совпали с летописным ходом. Это разные вещи, и их нельзя смешивать:
   можно выиграть не по-летописному и проиграть по-летописному.
3. **Шесть эпилогов**, и выбираются они по состоянию, а не по последнему нажатию.
   Исключение — два исхода последнего решения, «договариваться» и «готовить новый
   поход»: читать эту пометку больше негде, поэтому она решает финал сама.
   Канонический (летописный) путь ведёт к сильнейшему финалу — это закреплено тестом,
   но он не единственный: игра не должна превращаться в угадывание одного ответа.
4. **Неопределённость в данных, а не в сноске.** У `MapDirective` есть `uncertaintyKm`
   и `alternatives` — для мест, где точное положение неизвестно (стан шведов, место боя).
   `Outcome.uncertaintyNotes` собирает по ходу игры список мест, где источники молчат.
5. **Условия на вариантах.** У варианта есть `conditions` (по пометкам `session.flags`),
   но недоступный вариант **не прячется**: он показывается закрытым, и рядом стоит `note`
   — чем именно он закрыт («нужны суда — вы шли берегом»). Игрок должен видеть дверь,
   которую сам запер, а не пустое место. Страж следит, чтобы решений с условиями было
   не меньше десяти и чтобы каждое условие ссылалось на пометку, которую кто-то ставит.

## Чего здесь сознательно нет

- Сервера: движок и контент работают в браузере, отдельного бэкенда нет.
- Базы данных, админки, кабинета преподавателя — отложены.
- ИИ-советника: он появится, когда рядом встанет серверная часть.

Геометрия карты считается генератором `../tools/geo/build_geo.py` из Natural
Earth 1:10m и лежит готовой в `src/map/geography.json`; экраны — в `../web/`.
